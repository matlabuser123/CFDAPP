# Troubleshooting

| Symptom | Likely cause | What to do |
|---|---|---|
| `Case configuration error: ...` (exit code 2) | `case.json` or a file it references is missing, malformed, or has an invalid value | The message names the exact file and field (e.g. `solver.json: field "pressure_relaxation" must satisfy 0 < value <= 1; received 1.5`) -- fix that field. See [case_format.md](case_format.md). |
| GUI: "Validate" fails with a message | Same production validation as the CLI, run without solving | Same fix as above -- the message is identical to what the CLI would print for the same case. |
| Solve does not converge (exit code 3 / GUI state `Failed`, `Converged: no (max iterations reached)`) | Under-relaxation too aggressive for this mesh/Re, or `max_iterations` too low | Lower `velocity_relaxation`/`pressure_relaxation` in `solver.json`, or raise `max_iterations`. Not a bug -- SIMPLE's own convergence is not guaranteed for every setting. |
| `no (momentum solve failed)` / `no (pressure correction solve failed)` (exit code 4) | The inner BiCGSTAB linear solve itself failed to converge | Usually a very stiff case for the current mesh/relaxation -- try a smaller timestep-equivalent (lower relaxation) or a coarser mesh first. |
| `no (non-finite state)` (exit code 4) | Velocity/pressure went NaN/Inf mid-solve | Almost always too-aggressive relaxation or an unphysical boundary condition (e.g. contradictory pressure BCs on a fully closed domain) -- check boundaries.json against [case_format.md](case_format.md). |
| GUI: `Stop` doesn't stop instantly | By design (section 13) -- cancellation is only checked at the top of the next outer iteration, never mid-iteration, so the case's result files are never left partially written | Wait a moment; state becomes `Cancelled`, not `Completed`, once it actually stops. |
| `-DCFDAPP_BUILD_GUI=ON` but no `cfdapp_gui` was built | Qt 6 (Core/Gui/Qml/Quick/QuickControls2) wasn't found | Install it (see [installation.md](installation.md)) and reconfigure -- CMake prints a warning naming exactly this, rather than failing the whole build. |
| GUI QML fails to load (`Type ApplicationWindow unavailable` or similar) | A QtQuick Controls/Templates QML module is missing at runtime (distinct from the `-dev` packages needed to *build*) | On Debian/Ubuntu, `apt install qml6-module-qtquick-templates` fixed exactly this during development -- install whichever `qml6-module-*` package the error names. |
| CUDA unavailable | No NVIDIA GPU, or no CUDA driver | Expected and handled -- `cfd::gpu::cudaAvailable()` returns `false` and every CPU code path is unaffected; CUDA is never required (see the repository's own P4 status note). |
| VTK file won't open in ParaView / looks wrong | Usually opening the wrong file, or a failed/non-finite run (which does not write `fields.csv`/`solution.vtk` at all -- only `metadata.json`/`residuals.csv` are written unconditionally) | Check `metadata.json`'s own `numerics.finite`/`solver.status` fields first; a genuinely converged, finite run always writes all four result files (see [paraview.md](paraview.md)). |
| Case path invalid / permission or write failure | `--case`/GUI "Open" points at a directory CFDApp can't read, or `results/` can't be created/written | Check the path and directory permissions; a write failure is reported distinctly (exit code 1 / `Result export error: ...`) from an invalid *case* (exit code 2), so the message itself says which one happened. |
