# P18.5 — the analytical reference (§11, §48)

```text
G6 criterion (a), verbatim:
    "omega_i for a known mechanism against an INDEPENDENT arbitrary-precision implementation
     (Python/mpmath, no CFDApp code), over a matrix of T, p and composition spanning the intended
     range"
    threshold: relative error <= 32 * eps

THRESHOLD INHERITED, NOT CHOSEN. 32 eps is P17.7's own frozen multiple for the same kind of
pointwise closed-form comparison. It was not fitted to anything measured here, and nothing in
P18.5 moved it.
```

---

## 1. The reference, and why it is independent

`tools/arrhenius_reference.py` — mpmath at **60 decimal digits**, with no CFDApp code imported or
consulted. Everything in it is written from the physics:

```text
    R_i    = R_u / M_i
    R_mix  = sum_i Y_i R_i
    rho    = p / (R_mix T)
    C_i    = rho Y_i / M_i                 [mol/m^3]
    k      = A T^n exp(-Ea/(R_u T))
    q      = k Pi_i C_i^(nu'_i)            over REACTANTS, nu' not nu
    omega_i = M_i nu_i q                   [kg/(m^3 s)]
```

`R_u = 8.31446261815324 J/(mol K)` is stated as a literal in the script rather than imported, so
the two sides share not one symbol. Full output preserved at `data/reference_values.txt`.

The mechanism is `2 H2 + O2 -> 2 H2O` with `M_H2 = 0.002016`, `M_O2 = 0.031998`,
`M_H2O = 0.018015` kg/mol, chosen because `2 M_H2 + M_O2 - 2 M_H2O == 0` **exactly in binary** —
established in P18.4. Kinetics `A = 1.5e8`, `n = 0.5`, `Ea = 1.25e5 J/mol`.

## 2. Two independent comparison routes, deliberately redundant

```text
ROUTE 1  tests -- the reference's values become C++ literals, and the suite compares against them.
         The literals are GENERATED by tools/emit_cpp_cases.py from the same mpmath module, so no
         value is typed by hand.
ROUTE 2  probe -- CFDApp prints ITS numbers at 17 significant figures and tools/compare_probe.py
         recomputes the reference in mpmath and reports the error.

WHY BOTH. Route 1 cannot detect a wrong digit in its own literal table. Route 2 cannot be run
inside ctest. Together they close each other's gap: if the two ever disagree, one transcription
path is broken and the disagreement identifies which.
```

The first version of the matrix test carried **9 hand-typed rows**. When the generator was written,
it reproduced all 9 **exactly** — which is how the hand transcription was confirmed before being
replaced by the generated 36.

## 3. k(T) over the intended range — measured

`logs/05_mpmath_comparison.log`, 8 temperatures from 300 K to 3000 K:

| quantity | worst relative error | at | allowance |
|---|---:|---|---:|
| `k(T)` | **11.05 eps** | T = 300 K | 32 eps |
| `x = -Ea/(R_u T)` | **0.49 eps** | T = 800 K | 32 eps |

`k` spans **4.47e-13 to 5.47e7** — thirteen orders of magnitude — and the relative error does not
grow with it. The worst point is the coldest, where `exp(-50.11)` is smallest; that is where a
relative comparison is hardest, and it is still a factor **2.9 inside** the allowance.

## 4. The full G6 matrix — 4 compositions × 3 pressures × 3 temperatures

`logs/05_mpmath_comparison.log`. 36 rows: **27 with a non-zero rate, 9 with `C_H2 = 0`**.

| quantity | worst | at | allowance |
|---|---:|---|---:|
| `rho` (through P18.3's EOS) | **1.04 eps** | O2-rich, 10 bar, 1500 K | 32 eps |
| `q` | **10.24 eps** | stoich-ish, 10 bar, 800 K | 32 eps |
| `omega_H2` | **10.09 eps** | stoich-ish, 10 bar, 800 K | 32 eps |
| `omega_O2` | **10.12 eps** | stoich-ish, 10 bar, 800 K | 32 eps |
| `omega_H2O` | **10.04 eps** | stoich-ish, 10 bar, 800 K | 32 eps |
| `\|sum_i omega_i\| / scale` | **0.96 eps** | O2-rich, 10 bar, 2200 K | 32 eps |

```text
THE MARGIN IS 3.1x, NOT 1000x. That is worth stating plainly: the measured worst case is 11.05 eps
against an allowance of 32. The threshold was inherited rather than fitted, so the margin is what
it is -- but anyone tightening 32 eps in a later phase should know it would bite almost at once.

WHERE THE ~10 eps COMES FROM, and it is not a defect: q accumulates pow(C_H2, 2.0), a multiply by
C_O2, a multiply by k, and k itself carries pow(T, n) and exp(x). Each is correctly rounded
individually; around five of them compose to ~10 eps. omega_i then adds one multiply by M_i nu_i,
which is why omega tracks q to within 0.2 eps rather than drifting from it.
```

## 5. The exactly-zero rows — a sharper criterion, not a weaker one

The `no-H2` composition has `C_H2 = 0`, so `q = 0` and every `omega_i = 0`. A **relative** error is
undefined there, so those 9 rows are checked for **exact equality with 0** instead. Both the test
and the comparator assert this, and both refuse a log in which no zero row appears
(`logs/06_comparator_nonvacuity.log` case 5) — otherwise an implementation returning 0 everywhere
would take the exact branch for all 36 rows and the relative bounds would never be evaluated.

The matrix test carries the same guard as an assertion: `nonZeroCases == 27` and `zeroCases == 9`.

## 6. The reduced analytical cases (§9, §10, §11)

| case | expected | measured | result |
|---|---|---|---|
| `A = 0` | `k = 0` exactly, every valid T | exactly 0 | PASS |
| `Ea = 0` | `k = A T^n` | within 32 eps | PASS |
| `n = 0` | `k = A exp(-Ea/(R_u T))` | within 32 eps | PASS |
| `n = 0, Ea = 0` | `k = A` **bitwise** | `difference = 0`, bitwise **YES** | PASS |

The last one is why amendment A1 exists. Under the original log-space-always formulation it
measured `150000000.00000015` against `A = 150000000` — 4.5 eps in the case §11 calls "one of the
strongest simple analytical regression tests". That failure is preserved verbatim at
`logs/01_first_failures_PRESERVED.log`; see `formulation_A1.md`.

## 7. The Arrhenius plot (§35)

With `n = 0`, `ln k` is exactly linear in `1/T` with slope `-Ea/R_u` and intercept `ln A`.
Recovered from two evaluations at 800 K and 2000 K (`logs/04_probe.log`):

```text
  slope     -15034.04438034076   expected -15034.044380340756   1.09 eps
  intercept 18.826145852060531   expected 18.826145852060531    0.00 eps
```

The intercept is recovered **bitwise**. This is a *consistency* check on the implementation's
functional form, not an independent validation — it re-derives the same closed form — and is
labelled as such.
